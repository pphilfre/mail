# Mail productivity workflows

The profile button opens Accounts, the hamburger opens Mailboxes, and Emails returns to Inbox. Tasks pushes onto the current NavigationStack, including from the welcome screen, with native back and swipe-back navigation. The header and dropdown derive their active filter from the selected mailbox; filtering another mailbox keeps that scope and includes the filter in its title. Message rows identify receiving accounts with a vertical stripe.

Search provides sender, date, attachment-presence and account dropdowns alongside the existing typed operators. Date ranges use inclusive From and exclusive Before dates. Saved searches keep these filters and account scope, appear as smart folders in Mailboxes, and search downloaded messages. Create one using Search options → Save this search. Collections remain available for manually organised custom inboxes. Organisation rules match sender/subject within one or all accounts and archive, mark read, star or apply an account's label. A persistent revision marker prevents repeated execution on the same message; provider changes use the existing pending-operation queue.

Send queues a saved copy for ten seconds and offers Undo. Composer options → Schedule send saves a delivery date. Outbox shows scheduled, failed and uncertain deliveries and allows cancellation back to Drafts before sending begins. Queued attachments are retained. Scheduling is local: delivery happens when Dispatch is open, unlocked and online after the chosen time. Closing LiveContainer can defer delivery. No background extension, notification permission or additional entitlement is required. Interrupted or uncertain network sends are never automatically repeated; the existing Gmail sent-copy confirmation workflow remains available.

Manage signatures from Accounts or Composer options. The first signature is the default; long-press another to make it the default. Existing account signatures are available until migrated by editing the library. The composer can choose a different signature and manage shared templates/snippets. Templates fill an empty subject and insert body text; snippets insert body text. Existing body text is retained. Libraries persist on the device.

Attachments includes saved drafts and downloaded mail, Quick Look previews and local text search. Images and the first forty PDF pages are indexed on the device, with a thirty-megabyte per-file limit. PDFs containing text use that text; scanned pages use Vision OCR. Download files first to include their contents. OCR caches use complete file protection. The document-scanner button attaches a multi-page PDF through the existing attachment limits. Camera access is requested only for scanning.

Message actions is a compact scrolling sheet with medium/large detents and forty-four-point action targets. Save PDF exports the existing readable text copy. Save EML downloads and exports Gmail's original message bytes, preserving MIME and attachments. List-Unsubscribe headers enable unsubscribe actions: advertised one-click POST requests require user confirmation, with HTTPS-page or mailto-compose fallbacks. Header authentication is not independently verified; these actions do not label a sender as authenticated. Requests omit account credentials/cookies and refuse redirects. Missing unsubscribe endpoints produce no action.

Zoho has no connected provider in this checkout; its existing stub is preserved. These workflows do not add a simulated Zoho connection. Automated CI validates the simulator app and tests, while camera operation, permissions and LiveContainer-specific behavior still require checking on the phone.
