# Gmail provider

Native Google OAuth uses ASWebAuthenticationSession, a random state, PKCE S256, the registered iOS redirect and no client secret. Access/refresh credentials are stored only in Keychain. Token refresh is coalesced per account, preserves a refresh token omitted by Google, and rejects late refreshes after credential replacement/removal. Gmail requests refresh an explicit HTTP 401 once. Reads retry rate-limit 403, HTTP 429 and 5xx responses with bounded exponential backoff and jitter. Access-denied 403 responses retain a safe reason code for diagnosis. Sending and draft creation are never automatically replayed after a rate limit, network error or 5xx response.

GmailAPI contains REST transport and Sendable DTOs. Each account serializes transport requests and smoothly paces them at 60 quota units per second; sync, reader, attachments and mutations share that budget and server cooldown. Retry-After supports seconds and HTTP dates and is never shortened to the local backoff cap. Temporary mutation throttles stay queued rather than becoming permanent permission failures. GmailCoordinator owns orchestration on the main actor; GmailStorage maps values into SwiftData transactionally. Views read cached SwiftData before any network response. See the [403 and sync investigation](../../docs/gmail-sync-investigation.md).

Initial sync fetches the latest 100 All Mail entries plus 100 Inbox entries and caches full message bodies and attachment metadata. Mailbox and label selection fetch up to 100 recent matching messages, including Trash. Load older mail retains the active mailbox/label filter and a durable account-scoped cursor in StoreMetadata; cursors advance only after the page is cached. Legacy All Mail cursors remain compatible. Thread opening fetches the full thread. Labels are cached independently. Subsequent sync uses history.list and advances historyId only after all pages commit. A 404 history cursor triggers a new recent sync and reconciles every already-cached message. IDs remain opaque strings. Initial history is captured before fetching mail and drained afterwards.

Read/unread, star/unstar, custom-label add/remove, archive, trash and restore write a durable optimistic operation first. Operations are replayed serially before incremental sync; incoming DTOs retain overlays for operations still pending. Retry runs on launch, foreground, pull-to-refresh, and when a usable network path returns while the app is active. Background scheduling remains Stage 9. A usable path is a retry signal, not proof of Gmail reachability.

Save draft is local. Save to Gmail explicitly creates/updates a server draft, recovering a previous uncertain create by stable RFC Message-ID lookup. A durable marker blocks another create or send until that upload is resolved, including after a crash; a missing search result is not proof that creation failed. Existing server drafts can be edited/deleted/sent. Sending commits a durable sending state before the POST. Unknown outcomes become sendUnconfirmed and are displayed separately; they are never automatically resent. Check Sent searches Gmail using the stable Message-ID and confirms a found sent copy. Explicit 4xx rejection returns to editable draft. Interrupted sending is recovered on launch. No live email is sent by tests.

The composer checkpoints local edits after a short debounce and on lifecycle transitions. Discard removes a newly composed draft or restores the version opened. Remote draft editing/upload/sending verifies the immutable message revision for Dispatch-created drafts, including attachments; unknown drafts require plain text without attachments or external text bodies. Changed or unsupported content stays in Gmail rather than being silently replaced. Remote draft deletion is independent of import and requires confirmation. Unconfirmed outgoing copies appear in a dedicated account-scoped recovery view, with read-only Check Sent requests and no automatic resend.

Reply/reply-all preserve thread ID, original subject, References and In-Reply-To; recipient lists deduplicate and exclude the primary account address, and never copy Bcc. Changing the subject or account starts a new conversation. Forwarding offers original attachments or text only. Outbound MIME is UTF-8 with base64 text/binary parts, multipart/mixed attachments and folded encoded headers; header injection is rejected.

The reader uses nonpersistent WebKit views for HTML, selectable text and links opened externally. Older messages start collapsed and the opened message starts expanded. Recipient details expand separately; secondary reply actions use a menu. Page scripts, frames, forms and connections are blocked. Remote HTTPS images default to off, with a persistent Settings toggle and a per-thread override. Referenced CID raster images are fetched from Gmail when opening a thread (5 MB per image / 10 MB per message). Company website icons have a separate setting and initials fallback; these icons do not verify sender identity.

Received attachments download on demand (25 MB per file), preview in Quick Look, and share/save through the system share sheet. Protected account-scoped files reopen offline, retain cache identity across unchanged message syncs, and are removed with the account. A unified Drafts destination shows local edits and cached Gmail drafts using durable provider links to avoid duplicate rows. The composer attaches files/photos, saves protected originals with local drafts, and uploads/sends up to 20 files and 20 MB total. Forwarding copies attachments on request. See [attachment implementation](../../docs/composer-attachments.md). Arbitrary rich/attachment Gmail draft import and external text-body download remain deferred. Complex address groups, escaped quoted mailbox names and aliases require further parser work; the supported compose format is comma-separated addresses or Name <address>.
